# Kubernetes manifests

| File | Purpose |
|------|---------|
| `00-rbac.yaml` | ServiceAccount + **cluster-admin** binding 🔴 *(intentional weakness #5)* |
| `10-deployment.yaml` | NodeGoat deployment; `MONGODB_URI` env var from a Secret |
| `20-service-ingress.yaml` | NodePort Service + GCE Ingress → Google Cloud HTTP(S) LB |
| `40-seed-job.yaml` | One-shot `npm run db:seed` so there is data to prove |
| `90-preventative-gatekeeper.yaml` | 🛡️ Preventative control — denies **new** privileged pods |
| `99-privileged-pod-DENYME.yaml` | Demo prop — should be **rejected** by the above |

## Deploy
```bash
# 1. Cluster credentials (command is a Terraform output)
gcloud container clusters get-credentials wizex-gke --zone europe-west1-b --project <PROJECT>

# 2. Mongo credential Secret (values from tofu output + your tfvars — never committed)
kubectl create secret generic mongo-credentials \
  --from-literal=uri="mongodb://app:<PASSWORD>@<MONGO_INTERNAL_IP>:27017/todos?authSource=admin"

# 3. Point the manifests at the built image
sed -i '' "s|REGION-docker.pkg.dev/PROJECT|europe-west1-docker.pkg.dev/<PROJECT>|g" *.yaml

# 4. Apply
kubectl apply -f 00-rbac.yaml -f 10-deployment.yaml -f 20-service-ingress.yaml
kubectl apply -f 40-seed-job.yaml

# 5. Get the load balancer IP (takes a few minutes to provision)
kubectl get ingress nodegoat -w

# 6. Install the preventative control (Gatekeeper) — REQUIRED
just gatekeeper
```

> **The Kubernetes Secret is derived, not typed.** `just k8s-secret` reads the
> URI from Secret Manager and applies it. Re-run it after any Mongo rebuild —
> the address is reserved (`google_compute_address`), but the password is not.

> **Step 6 is not optional.** Without Gatekeeper installed, `90-preventative-gatekeeper.yaml`
> is inert and `99-privileged-pod-DENYME.yaml` is **admitted** — demonstrating the
> exact opposite of the intended control. `just gatekeeper` installs it and handles
> the two-pass apply (the constraint's CRD is generated by Gatekeeper from the
> ConstraintTemplate, so it does not exist on the first apply).

## Demo checklist
```bash
kubectl get pods,svc,ingress                                  # environment is healthy
kubectl exec deploy/nodegoat -- cat /app/wizexercise.txt      # required file, in the running container
kubectl get clusterrolebinding nodegoat-cluster-admin -o yaml # the cluster-admin weakness
kubectl apply -f 99-privileged-pod-DENYME.yaml                # preventative control REJECTS it
```

**Blast radius (the memorable moment):** the app's own token can read every Secret in the cluster —
```bash
kubectl exec deploy/nodegoat -- sh -c \
  'TOKEN=$(cat /var/run/secrets/kubernetes.io/serviceaccount/token); \
   curl -sk -H "Authorization: Bearer $TOKEN" https://kubernetes.default.svc/api/v1/secrets | head -40'
```
…and from the Mongo VM, the over-permissive service account can reach the cloud control plane:
```bash
gcloud compute instances list      # works, because the VM SA holds roles/editor
```

That pairing — vulnerable app → cluster-admin → cloud control plane, with backups already public — **is the toxic combination.**
